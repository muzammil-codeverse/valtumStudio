# Phase 3 authentication threat model

| Asset             | Threat / entry point                                    | Control                                                                                                      | Residual risk                                                | Verification                                                  |
| ----------------- | ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------- |
| Credentials       | Stuffing, brute force, or email enumeration at sign-in  | Generic failures; Better Auth DB limit; HMAC identifier throttle and temporary lock                          | Distributed attacks still need monitoring                    | Route/integration tests and `AuthThrottle` transaction tests. |
| Password choice   | Reuse or contextual password at change/reset            | 14–128 policy and email/product-term rejection; Better Auth hashing                                          | Breach-password lookup is deferred                           | Credential unit tests.                                        |
| Session           | Theft or fixation through browser/device                | Opaque DB sessions; `HttpOnly`, `SameSite=Lax`, production secure cookies; no cache; absolute cap            | Endpoint cannot detect a stolen legitimate cookie            | Cookie/integration tests and immediate revocation paths.      |
| Session           | Login CSRF, CSRF, or open callback redirect             | Exact trusted origins, route checks, constrained internal redirects                                          | Future external providers need separate review               | Origin-denial integration test and redirect unit policy.      |
| Identity          | TOTP or recovery-code theft during enrollment           | TOTP verification before codes display, no trusted devices, client-memory-only codes, acknowledgement gate   | Compromised endpoint remains high impact                     | UI flow review and server-side `trustDevice` rejection.       |
| Identity          | Recovery/MFA reset abuse                                | Confirmation-only operator scripts, revocation, high-severity events                                         | Operator identity is verified out of band                    | Script/integration tests and incident process.                |
| Authorization     | Role escalation or UI-only controls                     | Fail-closed role parser and centralized server matrix                                                        | New resources require matrix updates                         | Exhaustive role/resource/action test.                         |
| Ownership         | Last owner removal through ban/demotion                 | Transaction-level advisory lock and active-owner check; no delete primitive                                  | Concurrent direct SQL outside the app is out of scope        | Integration test attempts both operations.                    |
| Audit log         | Tampering or secret injection in metadata               | Application writes append-only events; bounded/redacted metadata; database roles must restrict direct writes | DB superuser can alter data                                  | Sanitizer review; production access policy remains required.  |
| Proxy attribution | Forged forwarded IP header                              | Header accepted only with configured proxy CIDRs; production fails on ambiguity                              | CIDR configuration must follow infrastructure changes        | Environment tests and deployment review.                      |
| Secrets           | Source/log/image leakage                                | Blank examples, runtime validation, generated CI/build values, logger redaction, non-root runner             | Host/process environment remains privileged                  | Static scan, Docker build/history review, audit.              |
| Database          | Credential or encrypted-storage compromise              | Least-privilege deployment role and backups/at-rest encryption are operational requirements                  | Better Auth tables include sensitive encrypted/hash material | Deployment review before launch.                              |
| Dependencies      | Compromised package or vulnerable transitive dependency | Exact pins, frozen lockfile, audit, Hono override, schema/CLI parity gates                                   | New CVEs can emerge after release                            | `pnpm audit --prod`, `pnpm why`, dependency policy.           |
| Docker            | Build secret or proxy-policy leakage                    | Build-only generated values; runtime values required; scoped lockfile exception with removal criteria        | Docker metadata still reveals command structure              | Docker build/runtime verification and ADR 0011.               |

The Phase 3 controls are an **ASVS Level 2-aligned Phase 3 baseline** across OWASP ASVS
4.0.3 V2 (authentication), V3 (session management), V4 (access control), V7 (error
handling/logging), and V14 (configuration). This is not an ASVS certification claim.
